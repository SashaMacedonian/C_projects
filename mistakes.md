# Ошибки и уроки (C)

## Строки и указатели

### str vs *str
- `while (str)`  → проверяет АДРЕС указателя (почти всегда true)
- `while (*str)` → проверяет ЗНАЧЕНИЕ по адресу (false при '\0')
- Мнемоника: звёздочка = заглянуть ВНУТРЬ коробки, без звёздочки = смотрю на саму коробку
- Потерял 5 минут на этой ошибке в my_strlen. Закреплено в задаче 2.3.

### Нулевой терминатор
- `'\0'` ≠ `0` ≠ `'0'`
  - `'\0'` = нулевой терминатор (код 0, конец строки)
  - `0`    = целое число ноль (работает идентично, но менее читаемо для строк)
  - `'0'`  = символ нуля (код 48, НЕ терминатор!)
- Правило: для строк ВСЕГДА использовать `'\0'` явно
- Консистентность: если в одной функции `'\0'`, то во всех функциях проекта тоже

### Копирование строк (strcpy)
- strcpy копирует ВСЁ от первого символа ДО '\0' ВКЛЮЧИТЕЛЬНО
- Если не скопировать '\0' → printf("%s") читает мусор из памяти (UB)
- Возврат: strcpy возвращает ИСХОДНЫЙ адрес dest, не текущую позицию после цикла
- Паттерн: сохранить `char* tempPtr = dest` до цикла, вернуть tempPtr после

### strcat
- Перезаписывает '\0' в dest первым символом src
- Нужно сначала найти конец dest циклом, потом копировать src
- Та же ловушка с возвратом: сохранять исходный адрес dest

## 07.09.2026
- **Ошибка: Модификация строкового литерала.** 
  Попытка изменить данные через `char *str = "Hello"; *str = 'h';` приводит к Undefined Behavior (чаще всего Segmentation Fault), так как литералы размещаются в read-only сегменте памяти (`.rodata`).
  *Решение:* Использовать `const char *str = "Hello";` для неизменяемых строк (компилятор заблокирует запись) или `char str[] = "Hello";` для копирования литерала в модифицируемую память стека.
- **Ошибка: Undefined Behavior в printf.** 
  Передача `NULL` в спецификатор `%s` (`printf("%s", NULL)`) является неопределенным поведением по стандарту C. То, что glibc выводит `(null)`, — это особенность конкретной библиотеки, а не гарантия. На других платформах это вызовет краш.
  *Решение:* Всегда проверять указатель на `NULL` перед выводом строки: `if (ptr) printf("%s", ptr); else printf("NULL");`.
- **Ошибка: Порядок проверок в цикле при поиске с конца.** 
  При реализации `my_strrchr` попытка сначала проверить условие выхода (`if (*end == '\0') break;`), а потом совпадение, приводила к пропуску проверки самого терминатора.
  *Решение:* Сначала проверять совпадение (`if (*end == c)`), затем проверять условие выхода (`if (*end == '\0') break;`).

- **Ошибка логики: путаница между поиском подстроки и проверкой вхождения символа.** 
  Пытался использовать логику `s[i + j] == accept[j]` (как в `strstr`) для задачи `strspn`. 
  *Решение:* `strspn` проверяет не последовательность, а принадлежность. Нужно для каждого символа `s` проверить, существует ли он *хотя бы один раз* в `accept`.
- **Ошибка инкремента счётчика:** Размещение `counter++` внутри внутреннего цикла приводит к завышению результата, если строка `accept` содержит дубликаты символов (например, `my_strspn("a", "aa")` вернёт 2 вместо 1). 
  *Решение:* Инкрементировать счётчик (или возвращать индекс `i`) только во внешнем цикле, после полной проверки внутреннего.

- **Паттерн: Early Return (Ранний возврат) вместо флагов.** 
  При поиске запрещенных символов (`strcspn`) не нужно использовать переменные-флаги (вроде `isFound`), которые инвертируют логику и усложняют чтение. 
  *Решение:* Если условие нарушения найдено внутри цикла, нужно немедленно делать `return` (или `break`). Это делает код плоским, читаемым и защищает от лишних итераций.
